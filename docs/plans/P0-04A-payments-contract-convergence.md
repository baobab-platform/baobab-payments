## Implementation and maintenance

`contracts.lock.yaml` declares all 19 consumed files, including the complete
schema reference closure and workload/scope vocabulary. The ten added paths
close undeclared consumers; the existing producer schemas remain byte-identical
apart from the reviewed additive capability enum. `scripts/sync_contracts.py`
reads exact Git blobs only at the lock commit, checks all references and owned
entries before mutation, and replaces the generated bundle so obsolete schemas
cannot survive. It generates `src/contracts_embedded.rs` and SHA-256 provenance.
Hand-written source is outside the replaced directory.

The Rust executable embeds its entire offline registry and verifies the manifest.
Validators are cached, draft 2020-12, with format assertions and retrieval disabled.
Eight authority entry points are checked at HTTP and consequential callback
boundaries. Stored Context UUIDs use the owner grammar independently of the
legacy assessment schema's broader opaque handle. Existing tenant/Organisation,
actor/mandate, exact operation, provider-readiness, negative-only documentary
leases and double refresh rules still decide whether execution may proceed.

The merchant-readiness route uses the exact owner request schema rather than a
local grammar copy. It still refuses to assert readiness without certification.
CP/IAM JSON rejects duplicate members recursively, invalid UTF-8/non-JSON numbers,
non-object roots and trailing input. Retained CP/IAM bodies are limited to
16 KiB/8 KiB while reading, including chunked responses; redirects remain disabled
and the existing three-second total timeout covers body completion. Contract
diagnostics report schema paths without echoing instance values.

## Verification and acceptance boundaries

The persisted 130-vector synthetic matrix checks all eight authority entries,
required/unknown/type/format/length/conditional cases and valid negative results.
The independent Python checker loads original owner Git blobs; Rust and the
standalone release executable consume the same cases. Existing producer/payment
lifecycle tests retain exact owner schemas. Docker builder probes prove the real
binary owns its assets without a checkout or schema network.

Additional tests prove malformed facts cannot reach readiness/mutation, invalid
local Context requests never contact IAM/CP, schema-valid foreign/stale Contexts
are denied by semantic checks, duplicates/redirects/oversized bodies are refused,
and a prompt header cannot hide a slow body beyond the complete deadline. Native
PostgreSQL CI is triggered by authority/contract changes as well as journal code.
No tests or protected gates are relaxed.

The local executor has no Rust toolchain or PostgreSQL service: local owner,
generation/inventory and syntax checks are distinct from hosted Rust/image/native
PostgreSQL evidence. Hosted CI is required before merge; no local compilation is
claimed. Golden vectors, synthetic certificates and loopback provider responses
are test facts, never genuine legal/merchant acceptance.

No production Payments assessment workload is registered at this pin. The
staging assessment profile remains PROVISIONED despite containing all three
context/legal/documentary scopes. This slice admits no workload, deploys no TLS
runtime and does not activate the sandbox for production. Real P0-03 records and
maker/checker decisions, PostgreSQL TLS/identity, certified merchant/beneficiary
and settlement/provider facts, full financial lifecycle and protected runtime
acceptance remain P0-04B/operator work. Next consumers: Subscriptions, Trade Docs.
