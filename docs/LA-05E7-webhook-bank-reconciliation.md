# LA-05E7 — HyperSwitch signed receipts, unmatched evidence and settlement

- `NativeWebhookReconciler` accepts only raw-body `x-webhook-signature-512` verified by constant-time HMAC-SHA512 using a server-owned HyperSwitch profile signing key. No webhook, tenant or URL can choose the key. A signed event is matched to a pre-existing provider observation **for the exact merchant, engine instance and environment** before appending a deduplicated immutable `provider_receipt` and `payments.provider-webhook.verified.v1` outbox event.
- Refund notifications use distinct `refund_details` content, require parent payment and refund reference, and refuse a refund amount exceeding the immutable originating amount. They are separate PSP facts, not settlements.
- `payment_ops.settlement_evidence` stores independently authenticated PSP and BANK statement lines under legal actor FORCE RLS. `unmatched_settlement_evidence` preserves verified unidentified lines as immutable exceptions rather than dropping foreign deposits. A `MATCHED` record requires canonical native order expectation, PSP gross/fee/net and independent bank net, currency/market, batch/provider-engine and payment reference consistency. Discrepancies are append-only exceptions; later corrected bank evidence does not rewrite earlier exceptions.
- Both `NativeWebhookReconciler` and `LocalSettlementJournal` deliberately permit only synthetic loopback/PostgreSQL 17 operation. `EvidenceVerifier` is an independent-source port; **no real bank/PSP signature verifier, account provider, settlement file importer or public secured webhook endpoint is installed**. Passing tests confirms local protocol and SQL invariants, not merchant/PSP certification, bank statements, reconciled payouts, or AWS readiness.

Pending: verified inbound webhook TLS/merchant routing/secret rotation; real PSP and bank statement custody+signatures; robust provider dispute/partial-refund ordering and journal dispatch cursors; ERP receivables matching; protected IAM tenant authority and staging/E2E evidence. Do not trigger canonical captured/settled ledger entries or production payouts from this code alone.
